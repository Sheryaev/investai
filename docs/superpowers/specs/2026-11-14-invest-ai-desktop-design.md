# Invest AI Desktop — проектная спецификация

Дата: 2026-11-14
Статус: утверждено пользователем 2026-11-14; реализация разрешена

## 1. Цель и границы

Создать локальное desktop-приложение для анализа инвестиционного портфеля в Т-Инвестициях. Приложение должно автоматически получать данные через T-Invest API, показывать основные показатели и интерактивные графики, а также предоставлять чат с выбором между Kimi, OpenAI/Codex и Claude.

Первая версия предназначена для Windows. Архитектура не должна препятствовать последующим сборкам для macOS и Linux.

Первая версия работает только в режиме чтения. Она не выставляет, не изменяет и не отменяет биржевые заявки. ИИ-агент не совершает торговых действий и не получает соответствующих полномочий.

## 2. Основные пользовательские сценарии

1. Пользователь один раз вводит read-only токен Т-Инвестиций и выбирает счета.
2. Приложение автоматически загружает портфель и показывает его стоимость, доходность, состав и операции.
3. Пользователь переключает периоды и фильтры, изучает графики и открывает карточки инструментов.
4. Пользователь выбирает Kimi, Codex или Claude и сразу получает анализ без ручного копирования данных и без уточняющих вопросов со стороны агента.
5. Пользователь переключает ИИ-провайдера внутри чата и сравнивает ответы на одном и том же снимке портфеля.
6. При временном отсутствии сети пользователь видит последний сохранённый снимок с явной отметкой времени.

## 3. Технологическая архитектура

### 3.1 Стек

- Electron — desktop-оболочка и безопасное локальное хранение секретов через `safeStorage`.
- React, TypeScript и Vite — пользовательский интерфейс.
- Node.js в главном процессе Electron — сетевые интеграции, расчёты, хранение и запуск локальных CLI.
- gRPC с зафиксированными protobuf-контрактами T-Invest API — интеграция с брокером.
- SQLite — нормализованный кэш, снимки портфеля и локальная история чатов.
- Apache ECharts — линейные, круговые, столбчатые и свечные графики.
- Локальные `kimi`, `codex` и `claude` CLI — основной способ подключения ИИ через уже выполненный пользователем вход, без API-ключей в приложении.

Собственный backend не создаётся. Главный процесс Electron является единственной доверенной частью приложения. Прямые HTTPS API с собственными ключами являются только необязательным запасным вариантом и не требуются для первой CLI-first версии.

### 3.2 Границы процессов

Renderer содержит только представление и состояние интерфейса. В нём отключены Node integration и произвольный доступ к ресурсам; включены context isolation и строгая Content Security Policy.

Preload предоставляет узкий типизированный IPC API. Через него нельзя выполнять произвольные сетевые запросы, читать файлы, получать секреты или вызывать произвольные методы главного процесса.

Главный процесс владеет:

- токеном Т-Инвестиций;
- gRPC-клиентом брокера;
- SQLite и миграциями;
- расчётами показателей;
- построением контекста агента;
- поиском и запуском выбранного локального CLI;
- потоковой передачей ответов агента в renderer.

### 3.3 Внутренние компоненты

- `InvestGateway` — счета, портфели, позиции, операции, инструменты, котировки и свечи.
- `PortfolioService` — нормализация ответов брокера, объединение выбранных счетов и создание снимков.
- `MarketDataService` — обновление котировок, получение свечей и управление временем актуальности.
- `AnalyticsEngine` — стоимость, доходность, доли, концентрация, изменения и исторические ряды.
- `SnapshotRepository` — транзакционное сохранение снимков, операций и временных рядов.
- `CliDetector` — поиск `codex`, `kimi` и `claude`, версия и состояние входа без платного тестового запроса.
- `AgentHub` — единый интерфейс CLI, потоковые ответы, отмена и запрет скрытого переключения.
- `PortfolioContextBuilder` — автоматический компактный контекст без секретов и лишних идентификаторов.
- `ChatRepository` — локальные диалоги, сообщения, выбранный CLI и идентификатор снимка.
- `SecretStore` — шифрование и расшифровка токена брокера только в главном процессе.

## 4. Интерфейс

### 4.1 Обзор

- Общая стоимость выбранных счетов в базовой валюте.
- Свободные денежные средства.
- Абсолютная и процентная прибыль за день и за весь доступный период.
- График стоимости с периодами `1Д`, `1Н`, `1М`, `3М`, `1Г`, `Всё`.
- Распределение по типам активов, валютам и счетам.
- Крупнейшие позиции и инструменты, внёсшие наибольший вклад в изменение стоимости.
- Время последнего успешного обновления и состояние соединения.

### 4.2 Портфель

Таблица позиций поддерживает поиск, сортировку и фильтры по счёту и типу актива. Для каждой позиции отображаются:

- тикер и название;
- количество;
- средняя цена, если её предоставляет брокер;
- текущая цена;
- стоимость;
- доля в портфеле;
- абсолютная и процентная доходность.

Карточка инструмента содержит свечной график, объёмы, доступные справочные данные, текущую позицию и связанные операции. Из чата можно открыть соответствующую карточку.

### 4.3 Аналитика

- Динамика стоимости и доходности.
- Структура и концентрация портфеля.
- Доли крупнейших позиций и эмитентов при наличии данных.
- Валютная структура.
- Отраслевая структура только для инструментов, для которых брокер возвращает отрасль; остальные объединяются в категорию «Не указано».
- Операции, пополнения, выводы, сделки, дивиденды и купоны с фильтрами по периоду и счёту.

### 4.4 ИИ-чат

- Переключатель `Codex / Kimi / Claude` доступен перед каждым новым запросом.
- Приложение само находит установленные CLI и показывает «Не установлен», «Установлен», «Требуется вход» или «Готов».
- Для входа предлагаются `codex login`, `kimi login` либо интерактивный запуск `claude`; API-ключи не запрашиваются.
- Модель по умолчанию берётся из конфигурации выбранного CLI; при необходимости пользователь может задать её идентификатор.
- Быстрые действия: «Проанализируй портфель», «Найди риски», «Что изменилось?», «Разбери выбранную позицию».
- Ответ выводится потоково, поддерживает Markdown, таблицы и ссылки на экраны приложения.
- Возле каждого ответа отображаются CLI и время снимка портфеля.
- Пользователь может остановить генерацию и повторить запрос.
- История диалогов сохраняется локально. Если включено продолжение сессии CLI, отдельное предупреждение сообщает, что CLI может хранить собственную историю.

Агент не задаёт уточняющих вопросов в штатном сценарии. Если данных недостаточно, он явно указывает ограничение и выполняет возможный анализ по имеющимся данным.

### 4.5 Настройки

- Добавление, замена и удаление токена Т-Инвестиций.
- Выбор счетов и базовой валюты.
- Повторное сканирование CLI, инструкции по установке и входу, выбор модели и управление историей сессий CLI.
- Частота автоматического обновления.
- Экспорт диалога в Markdown.
- Очистка кэша, истории чатов и всех локальных данных с подтверждением.

## 5. Данные и расчёты

### 5.1 Загрузка и обновление

При запуске сначала загружается последний локальный снимок, затем начинается фоновое обновление. Счета и портфели запрашиваются по выбранным счетам; независимые запросы выполняются параллельно с учётом ограничений API.

Котировки обновляются автоматически через поток рыночных данных, когда он доступен. При разрыве потока используется переподключение с экспоненциальной задержкой и ограниченный polling как резерв. Свечи и операции загружаются по требованию и кэшируются по инструменту и периоду.

Каждый снимок содержит время формирования и состояние полноты. Частичные данные не смешиваются с новыми без отметки. Ошибка обновления не удаляет последний корректный снимок.

### 5.2 Точность

Денежные значения и количества представляются десятичными типами либо целыми значениями в минимальных единицах. Обычный JavaScript `number` не используется для финансовой арифметики, где возможна потеря точности.

Отсутствующее значение отображается как «Н/Д», а не как ноль. Валютные преобразования содержат использованный курс и его время. Несогласованные данные брокера не скрываются расчётом молча.

### 5.3 История

Новые снимки сохраняются локально и образуют фактическую историю со времени установки. Более ранняя история восстанавливается из операций и рыночных свечей. Восстановленные значения помечаются как расчётная оценка.

Если корректная реконструкция невозможна из-за корпоративных действий, переводов между счетами или отсутствующих свечей, затронутый интервал обозначается как неполный. Приложение не показывает ложную точную доходность.

## 6. Автоматический контекст агента

Перед запросом `PortfolioContextBuilder` формирует версионированный JSON-снимок:

- базовая валюта и время данных;
- суммарная стоимость, денежные средства и доходность;
- позиции с тикерами, количествами, ценами, стоимостью, долей и доходностью;
- распределение по активам, валютам и счетам с обезличенными названиями счетов;
- последние операции и изменения относительно предыдущего снимка;
- рассчитанные показатели концентрации;
- выбранная позиция и период открытого графика;
- отметки неполных или оценочных данных.

В контекст не включаются токены, API-ключи, номера счетов, персональные данные, содержимое других диалогов и произвольные локальные файлы.

Для штатного анализа полный снимок передаётся выбранному локальному CLI автоматически, без подтверждения каждого сообщения. CLI и время отправляемого снимка постоянно видны в чате. Скрытое переключение провайдера запрещено.

Полный контекст формируется заранее, поэтому собственные tools внешнего агента отключены. Kimi получает generated agent profile с `tools: []`; Claude — пустой `--tools` и запрет MCP; Codex — read-only sandbox, отключение пользовательских правил и ephemeral-запуск. CLI не получает методов торговли, токена брокера или доступа к проекту.

Системные инструкции требуют опираться на числа снимка, указывать время данных, отделять факты от интерпретации и не выдавать неопределённость за точный прогноз. Ответы сопровождаются кратким обозначением, что это аналитика, а не индивидуальная инвестиционная рекомендация.

## 7. Безопасность и приватность

- Для брокера используется токен только с правами чтения.
- Токен шифруется через Electron `safeStorage`; на Windows защита использует механизм текущей ОС.
- Токен не записывается в SQLite в открытом виде, не попадает в журналы, IPC, аргументы CLI, контекст агента и экспорт.
- Локальная база не считается шифрованным хранилищем секретов.
- Выбранный ИИ-провайдер получает финансовый снимок через собственный CLI только при обращении пользователя к чату или запуске быстрого действия.
- CLI запускается без shell в пустой рабочей папке, с timeout и отменой; при завершении не остаются дочерние процессы.
- По возможности prompt передаётся через stdin, а не аргументы процесса. Собственная история сессий CLI отключена по умолчанию; если пользователь её включает, приложение предупреждает о хранении истории самим CLI.
- Провайдер не меняется автоматически при ошибке, чтобы исключить неожиданную передачу данных и списания.
- Внешние ссылки открываются через безопасный системный обработчик, а не внутри привилегированного окна.
- Зависимости и protobuf-контракты фиксируются lock-файлами.

## 8. Ошибки и диагностика

Единые категории ошибок: авторизация, недостаточные права, ограничение частоты, сеть, некорректный ответ, неподдерживаемая модель, недостаточный баланс провайдера и локальное хранилище.

Приложение:

- объясняет проблему на русском языке и предлагает конкретное действие;
- соблюдает серверные ограничения и задержки повторов;
- не создаёт бесконечный цикл автоматических повторов;
- позволяет вручную повторить запрос;
- показывает устаревший снимок при сбое обновления;
- сохраняет очищенный от секретов диагностический журнал с ограниченным размером.

## 9. Производительность

- Последний сохранённый обзор должен становиться доступным сразу после инициализации локальной базы, без ожидания сети.
- Обновления котировок не должны блокировать прокрутку, переключение экранов и ввод сообщения.
- Большие таблицы и временные ряды используют пагинацию, виртуализацию или downsampling в зависимости от размера.
- Одновременные записи SQLite сериализуются; длительные расчёты выносятся из обработчика событий интерфейса.
- Повторный запрос тех же свечей или операций использует действующий кэш.

## 10. Тестирование

### 10.1 Модульные тесты

- Денежная арифметика и округление.
- Объединение счетов и валютные пересчёты.
- Доходность, доли и концентрация.
- Частичные и отсутствующие данные.
- Построение контекста и удаление запрещённых полей.
- Ограничение числа вызовов инструментов агента.

### 10.2 Контрактные тесты

- Нормализация записанных ответов T-Invest API.
- Адаптеры трёх ИИ-провайдеров, включая потоковые фрагменты и ошибки.
- Миграции SQLite и совместимость версий снимков.

Секреты и реальные персональные ответы не включаются в тестовые записи.

### 10.3 Интеграционные и end-to-end тесты

- Первичная настройка и повторный запуск.
- Загрузка портфеля и работа с кэшем без сети.
- Неверный или read-only недостаточный токен.
- Пустой, мультисчетовой и мультивалютный портфель.
- Фильтры, периоды, карточка инструмента и операции.
- Выбор каждого агента, потоковый ответ, отмена и повтор.
- Автоматический контекст без уточняющих вопросов.
- Сбой провайдера без скрытого переключения.
- Закрытие приложения во время обновления и восстановление базы.

### 10.4 Ручная приёмка

Проверка с реальным read-only токеном выполняется только на данных владельца. Сверяются основные суммы с официальным приложением брокера; допустимые расхождения должны объясняться временем котировок или явно обозначенной оценкой.

## 11. Сборка и поставка

Первый результат — Windows-инсталлятор, созданный через Electron Builder. При наличии сертификата сборка подписывается; отсутствие сертификата не блокирует локальную сборку, но явно указывается пользователю.

Обновление приложения, автоматическая загрузка релизов и публичная инфраструктура распространения не входят в первую версию. Команды разработки, тестирования и сборки документируются в проекте.

## 12. Критерии готовности первой версии

1. Windows-приложение устанавливается и запускается без среды разработки.
2. Read-only токен не отображается после сохранения и не попадает в журналы или процессы CLI.
3. Пользователь видит актуальный портфель, основные показатели, операции и графики.
4. Все выбранные счета корректно объединяются с учётом валют и времени данных.
5. Устаревшие, неполные и расчётные значения визуально отличаются от актуальных фактических.
6. Codex, Kimi и Claude доступны через единый чат при наличии установленных авторизованных CLI; API-ключи не требуются.
7. Агент автоматически анализирует актуальный портфель без уточняющих вопросов и ручного копирования.
8. Агент не имеет торговых функций и доступа к секретам.
9. Потоковый ответ можно остановить; ошибка одного провайдера не вызывает скрытого переключения.
10. Автоматические тесты и Windows-сборка успешно выполняются в чистом окружении.

## 13. Вне первой версии

- Любая торговля и передача заявок агентом.
- Мобильные приложения и собственный облачный backend.
- Автоматические инвестиционные рекомендации по расписанию и push-уведомления.
- Сравнение с внешними индексами, требующее дополнительного источника данных.
- Налоговые декларации и бухгалтерский учёт.
- Совместная работа нескольких пользователей.
- Поддержка других брокеров.
